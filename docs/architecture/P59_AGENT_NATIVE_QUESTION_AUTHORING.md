## Product architecture verdict

For 90–95% generated content, the best default is **external source-grounded AI → small structured files → deterministic headless checks → focused corrections → offline Practice Desk import/staging → optional Wordgard review → immutable publication and scoring**. Do **not** ask an agent to open and click hundreds of Wordgard questions. The editor is the 5–10% exceptional manual correction pathway, not a mandatory per-question integration API. Do not embed prompt scaffolding, internal SHA envelopes, all historical attempts or full app repository source in each generation request.

One model of the same quality with equivalent source evidence has no intrinsic quality gain from running inside the app versus in ChatGPT. The app is better at persistence, evaluation, versioning and question selection; research tools/model access outside the app are better for primary-source verification. Browser automation usually costs *more* interaction/context than exchanging small JSON and CLI results. **Source SHA, JSON validity, independently repeated AI answers and reviewer labels are not proof of true facts**. Legal topics need current primary-source retrieval and commencement/as-of checks.

### Required agent handshake (no full repository read)

1. Read this brief guide plus `examples/ai-first-apfc.json` or `examples/ai-first-cat.json` **once per new exam family**, then author `practice-desk-authoring` v1 in batches of ~10–30 independently researchable questions. Use a stable `bankId`, stable `question.id`, `provenance.kind:"ai-original"`, `qa.status:"unchecked"` or `needs-review`; provide explanatory proof and explicitly **attributed source citations** without inventing publisher, title, section, provision, publication dates or access history. Keep answers out of pre-submission exercise UI.
2. Run existing `node scripts/question-bank-cli.mjs qa-bank input.json` or the new compact `node scripts/question-bank-agent.mjs inspect input.json`. **Never publish** when structural/verified-math errors remain. The CLI still marks external verification `not-performed` and editorial `caution`. Follow up factual disputes *outside* the app; do not accept the appearance of a citation as fact verification.
3. Use `node scripts/question-bank-agent.mjs show input.json question-id` to retrieve **one** question, its read-only digest and referenced stimulus/media metadata (no base64 media bytes). Create a small patch `{format:"practice-desk-agent-patch",version:1,baseSha256:"<inspect SHA>",updates:[{id:"question-id",expectedQuestionSha256:"<show SHA>",set:{"answer":"C","explanation":"..."}}]}`. Apply with `node scripts/question-bank-agent.mjs patch input.json patch.json corrected.json`. Patches are **new output files only**; stale source/item digest, unknown fields, bad answer key and nonviable QA all fail closed. Set optional `nextRevision` to a larger integer for an explicitly new candidate revision; this alone does not authorize replacement of a published bank or any historical score.
4. Upload the corrected **AI source v1** into the offline Library (or Wordgard staging across files). For corrected rich Wordgard-only drafts, use their separate versioned **`practice-desk-draft-exchange` v1**; it round-trips through the same publisher, whereas a reverse conversion to narrow AI source v1 is deliberately **not** lossless. Import/accept warnings requires human action under the established caution policy; final exams/attempts are frozen.
5. Store agent sources, external source extracts/links (when licensed and authorized), compact QA reports and revision patches alongside your source project. Keep exported staging and draft-shelf archives **separate** from History v4. The agent never writes IndexedDB, invents `verified` statuses or edits internal compiled hashes.

### Question quality rubric (not replaced by JSON validation)

- **Factual and temporal correctness:** find the primary document; compare current provisions, Gazette commencement, amendments, rules and as-of date. Two independent sources when critical, with disagreements explicitly marked for research. Current affairs dates and numerical rates must be checked.
- **One defensible keyed answer:** each distractor must be demonstrably wrong (not merely less popular), stems must be unambiguous with applicable jurisdiction/date and no accidental clue, and each option must be justified. For legislation, identify exceptions and distinguish predecessor Act from current Code when applicable.
- **Construct relevance:** match the *official broad heading*, a plausible APFC/CAT skill and realistic difficulty; do not drift into marginal specialist CA/legal material without PYQ basis. Distinguish physical exam section from academic subject/topic/subtopic.
- **Learning value:** explanation supplies mechanism/legal reasoning and reasons alternatives fail; errors and guessed concepts should map to topic/revision queue. Do not label an AI paraphrase an official PYQ.
- **Bias, duplication and integrity:** avoid repeated wording/answer-position patterns, invalid answer distributions, close duplicates across banks, leakage of answer into prompt or options, and misleading verified/reviewer flags.
- **Measured checking:** code can validate schema, immutable publication, scorer agreement, certain trivial arithmetic, duplicates and existence of source metadata. It does **not** fetch/understand the cited laws or certify educational quality, even after a second model review.

### Context, tokens and efficiency

An agent should ingest **this narrow format + the local question(s) being repaired + bounded QA issue output**, not entire app source, browser screenshots, 400 questions, the ledger and every past attempt. The new headless `inspect` defaults to **12 issues per page** with `--offset` and `--limit`, and `show` exposes only one item plus non-base64 asset metadata. JSON patch payloads carry changed fields only, protected by file/item SHA preconditions. Large shared stimuli should be authored once and referenced; source IDs persist into publication. Total model cost still depends on source retrieval, topic difficulty and how much context the agent is given; the CLI is a *lower interaction overhead*, not a promise about a model's token count or accuracy.

### Invariants, 5-step QA and external holds

- Reinspect source and write pre-fix/contract tests; implement a **standalone Node 24 agent adapter**, not another scoring system or browser service.
- Strict schema, bounded output/paging, stable hash on raw source file and canonical selected question, no hidden overwrite, no partial files, no arbitrary document mutation, no unsafe path interpretation, no content/verified inflation; source 25MiB guard. Substantive question corrections automatically reopen the author-supplied `needs-review` flag; when an item is labelled `official-pyq`, editing its original wording, options or answer requires an explicit provenance update rather than silently retaining a potentially false historical-exam claim. This is a review guard, **not** external source authentication. Patches must pass existing external compiler/QA before file write.
- End-to-end tests: compact default and paging, no media data URI exfiltration in `show`, valid patch/next revision, stale hash/unknown ID/unexpected field/invalid answer reject, no original modification, output creation fail-closed, current app compiler parity; actual full CI still gates acceptance.
- No database migration, server, new app route, vendor replacement, dynamic network, source fact checker, automated historical result rewrite or UI paper-by-paper click loop.
- Physical macOS/iOS/Android, real AT/IME/OS eviction, independently sourced full APFC/CAT content, human visual approval, distribution and merge remain **external** and cannot be claimed from headless CI.
