## 3. Fresh cross-boundary defect P56-R1 — real reproducible failure

**Evidence, pre-fix red:** [CI 41956895347](https://github.com/oneshubhamt/practice-desk/actions/runs/41956895347), source `5082ba2f9d25811627a09c78c8873f788222a359`, Chromium job `127013983293` failed the *new* independent `scripts/acceptance-p56-integration.mjs` on a genuine file:// browser. It initialized importing tab A, then tab B committed a valid same-source content digest and a different completed attempt to the shared IDB. Tab A imported a correct SHA-verified portable v4 backup for another attempt referring to exactly the same immutable digest. Result: visible **“Import failed”**; additive second record absent. The original old CI was green because its import examples never exercised stale cross-tab digest cache.

**Source root cause:** `src/app/persistence-controller.ts:importHistoryBackup` used `owner.storedSnapshots.has(id)` to decide `snapshotStore.add(snapshot)`. The cache is populated only at this tab's startup/import; an independent tab may have added the digest in the meantime. Attempt import and snapshot add occur in one IDB readwrite transaction, so the duplicate-key constraint atomically aborted otherwise-valid new attempts.

**Scoped repair:** commit `88ab4dc3202abcb8daefc43bcc3819486d2694a3` changes the import *transaction only*: run `snapshotStore.get(id)` in the same two-store readwrite transaction; if absent, add verified archive snapshot; if present, invoke `verifiedSnapshot` for exact digest integrity, reuse unmodified valid source; if corrupt, abort the entire transaction and leave pre-existing bytes untouched. All source/key/score/lineage validators, v4 envelope, CAS, no-overwrite/import confirmation, schema and public UI remain unchanged. It does not turn SHA-256 into an author signature.

**New negative:** the same browser scenario seeds a same-ID snapshot whose stored body was tampered after the ID was derived; valid incoming archive must NOT repair or overwrite it and must NOT import a partial attempt. Test `scripts/acceptance-p56-integration.mjs` runs this in a fresh browser context. The initial negative test's UI wait expected generic “Import failed” rather than the more precise **“Shared snapshot SHA-256 mismatch”**; its wait was corrected without weakening the no-overwrite checks. All real engine and strict gates still required.

## 5. Threat model, quality and release boundaries

- **Integrity:** Domain validators reject unsigned extra fields, malformed keys, misleading marks, imported clock totals, forged question/source hashes; complete score re-computed from frozen state. Portable v4 SHA-256 is corruption evidence, *not proof of origin*. Newly discovered same-SHA concurrent import must reuse independently verified existing digest; an invalid digest must abort without write.
- **Confidentiality:** CSP built from the exact executable SHA-256 inline script; `script-src-attr 'none'`, `connect-src 'none'`, local fonts/media. Author-only worked keys preview separately disclosed; candidate detailed review is withheld when `allowReview=false`. An offline file contains its own answer key: local file/system access is **outside** the embargo.
- **Performance:** P55 reported 12 synchronous headless Linux Chromium redraws at 100/500 cases; P56 does not invent a speedup or device representative result. Current History reads can still retain many records and are not paged/indexed; storage growth/quota remains operational caution.
- **Test boundary:** Real Playwright browser engines run Linux CI, not a user-owned Mac. Simulated composition/195px zoom supports software checks only. No real screen-reader, touch gesture or physical IME certification, no OS reboot/eviction data preservation, no independent external exam-source verification and no manually approved screenshot quality.
- **Release:** strict hold. No merge to `main` or `baseline/v11`, no new bank contents and no distribution authorization merely because code/test gates succeed.
