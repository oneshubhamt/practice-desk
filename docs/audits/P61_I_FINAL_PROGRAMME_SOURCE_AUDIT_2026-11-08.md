## 4. Retained unique P0/P1 safeguards and residual uncertainty

- **PDF and external-source truth:** `tests/p60e-pdf-ingest.test.mjs` uses a real *synthetic* structured PDF to exercise page/digest/intake gates, key vs original identity, corrupt PDF rejection and stale lineage. It does **not** OCR, visually inspect or independently verify a supplied source document, official PYQ identity or correct legal/statutory answers. Synthetic tests must not be described as factual verification.
- **Storage and concurrency:** preserve 250×150 interleavings, 576-case saved/mirror property, snapshot corruption quarantine, additive v4 digest and 200-seed merge, real browser two-tab/quota/recovery scenarios. Synthetic browser storage does **not** prove real-device OS eviction recovery.
- **Scoring and six kinds:** independent 200-seed policy oracle is single-choice; the new independent 128-seed six-kind model covers verified marks/verdicts, exact multi-select sets and ID/order invariance. Separate exact APFC negative marks (unrounded), partial-credit cap, numeric tolerance and authentic candidate browser result tests remain necessary.
- **Authoring, candidate secrecy, editorial provenance:** signed rich publishing, actual six-kind candidate UI, locally bound source-vs-reviewed keys, and P60-C answer-leak checks remain. **P60-01** (explanation-only assets potentially exposed) and **P60-03/04/05** original/reviewed comparisons are still deferred findings; clean CI does not establish remediation.
- **Learning/FSRS:** actual explicit ratings, replay persistence, exam-scoped source evidence and review embargo checks remain distinct from content correctness and long-term pedagogical efficacy.
- **Physical accessibility/release:** real Mac Safari, iOS/Android, screen readers, keyboard+IME, physical storage eviction, human 195px visual judgement and independent printed PDF/PYQ comparison have **not** been completed by Linux CI. The retained 195px/140% test is synthetic browser geometry, not a blanket accessibility certification.
- **Deferred programme scope:** all P60-01–07 items (P60-06 documentation guidance partly corrected), calendar/survey proposals, genuinely source-verified question banks and publication/user approval remain in [the active backlog](../../backlog.md) and are *not* hidden as solved by P61.
- **Unverified opt-in screenshot journey:** `visual-evidence.test.mjs` tests the default and opt-in mock; full manual visually reviewed screenshot capture is not included in routine CI, by intentional design.

## 5. Closure rule and handoff

P61-I is **eligible to close** when exact changed-SHA full protected CI logs confirm:
1. Node 24 strict typecheck, build, deterministic HTML and **408/408 Node tests**;
2. **10/10** distinct *baseline-green, assertion-killed* source-isolated mutants;
3. **32/32 Chromium + 20/20 Firefox + 20/20 Linux WebKit**, with each original script executed and a fully closed browser pool;
4. guarded, source-verified HTML publisher **PASS**, with no `src/`, `examples/`, `package.json` or production HTML changes; and
5. current docs, guide/index, backlog and CI mutation label accurately mark P61 completed and retain deferred P60/device/content risks.

The current test bench should stay intact unless a **new, specifically approved scope** is supported by assertion-level counterexamples and real regression verification. Never resume mass test deletion merely to satisfy count/LoC targets. **P61 closure does not authorize P60 fixes, branch merges, public release, physical-device certification or question-bank authenticity claims.**
