## Non-negotiable development contract

- **Branch:** only commit to `overhaul`; never modify `main` or `baseline/v11`; do not merge without explicit user approval.
- **Product:** the historical v11 parity programme is complete. Future development is **forward-looking**, improving a generic, multi-exam offline study application beyond v11. Protect current supported user workflows and regression contracts; do not treat historical v11 layout, styling or pixel geometry as a design ceiling or a required comparison oracle.
- **Artifact:** one generated self-contained offline `file://` HTML, no runtime internet, analytics, remote scripts/fonts or account. Never edit generated HTML directly.
- **Engineering:** typed, modular strict TypeScript, one six-kind exam runtime, no untyped parallel v11 implementation or casual `any`/`@ts-ignore`/`@ts-nocheck`.
- **Integrity:** immutable content-hashed paper/question/key/media snapshots, original/reviewed provenance; scoring and answer events validated and frozen; race-safe `saveRevision`, checked additive backup v3, explicit self-assessed writing marks and FSRS ratings; no pre-submit key disclosure.
- **Editorial:** user-approved reviewed CGL `caution` fallback retains published key B in disputed 6 Oct Q62 and scores it (+2/−0.5), while original source invalid is excluded. Dispute is disclosed clearly only after submission. The real paper/key JSON must remain unchanged.
- **Scoring:** component partial marks must not exceed declared full credit; validated blank awards, negative mark floor, matching uniqueness and multiple-select key/cardinality envelopes were repaired in Pass 17 and independently rechecked in Pass 23. Never relax these constraints merely to satisfy fixtures.
- **Backup:** no v11 history migration (new app) and no replacing existing record IDs on v3 import.
- **Engineering process (MANDATORY EACH PASS):** audit actual source, consumers, contracts and active scratchpad → analyse alternatives, failure modes and invariant impact → implement on `overhaul` → check each objective against source and independent evidence → targeted QA plus appropriate full gates. Keep a living Markdown log with tests genuinely executed and unresolved limitations; do not claim success before green CI. Prefer capability-oriented files and suites over chronological pass-numbered code.
- **Mandatory CI:** Node24 strict typecheck/build, all independent Node/property tests, modern `file://` Chromium acceptance (`scripts/acceptance-critical.mjs`, `acceptance-bank-modes.mjs`, `acceptance-drafts.mjs`, `acceptance-recovery.mjs`, `acceptance-ui.mjs`, `acceptance-stress.mjs`, `acceptance-platform.mjs`), Firefox/WebKit offline persistence and navigation with honest engine-availability disclosures, plus any focused legacy tests that still enforce unique current correctness/safety behaviour. Do not drop checks merely to make CI green.
- **Visual-testing policy (user decision 1 Nov 2026):** **no routine historical v11 parity runs, pixel comparisons, screenshot matrices, or large screenshot artifact warehouses.** Assert current DOM/layout, responsiveness, focus, accessibility semantics, overflow and usability at representative viewports. Capture screenshots only on a failed scenario or when an explicit new visual review warrants them. User-approved future design is allowed to differ from v11. The frozen `baseline/v11` and Pass29/Pass30 reports remain archived evidence, not mandatory CI.
- **Current multi-exam contracts:** Library original/reviewed CGL buttons actually filter eligible options, with imported exams grouped separately; preserve same-family switching, real preview/scoring rules, accessible Start. Independently persistent Untimed must derive immutable policy and function across strict/flexible/single CGL and imported exams. Simplified `practice-desk-bank` MCQ/NAT with downloadable offline APFC template and advanced six-kind `practice-desk-exam` remain supported. Test via capability-oriented `tests/exam-bank-and-policy.test.mjs`, `scripts/acceptance-bank-modes.mjs`, and generic suite, **not** by requiring historical `pass30-bank`, `pass30-ui` or Pass29 paths. Protect 195px/140% overflow with direct modern assertions.
- **Offline Mac navigation:** prefer native Navigation API where fully supported, but a feature-detected same-document fragment router **must** handle missing or rejected file:// Navigation API on Safari/WebKit. Preserve real Back/Forward, route-hash deep links, resumed attempts, and the no-network standalone HTML. The modern `acceptance-safari-fallback.mjs` is mandatory in Chromium, Firefox and WebKit CI; browser support must not be claimed from a mocked API alone. Recorded Safari WebKit native-history limitations and actual physical Mac testing remain distinct.
- **Responsive Results at extreme magnification:** **195 CSS px plus 140% in-app font size** must not overflow the document in bank/mode Results; check `acceptance-bank-modes.mjs` at the combined setting, rather than separate partial checks.
- **Release/claims:** publish self-contained HTML only after all applicable CI gates, with `contents:write` limited to guarded publication; PR/test jobs read-only. No physical-device, macOS Safari/iOS/Android, screen-reader, storage eviction, OS-kill or full WCAG conformance claims from browser emulators alone. Native WebKit Back after a `file://` reload is not currently verified; do not mask unavailable support with a fake pass.
- **Documentation:** keep the docs index, active scratchpad, architecture, data contracts, decision register and current verification status consistent. Retain old audit reports as dated historical evidence and do not rewrite their original findings. Do not create competing chronological diaries.
