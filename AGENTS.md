## Non-negotiable development contract

- **Branch:** only commit to `overhaul`; never modify `main` or `baseline/v11`; do not merge without explicit user approval.
- **Product:** the historical v11 parity programme is complete. Future development is **forward-looking**, improving a generic, multi-exam offline study application beyond v11. Protect current supported user workflows and regression contracts; do not treat historical v11 layout, styling or pixel geometry as a design ceiling or a required comparison oracle.
- **Distribution:** a self-contained offline `file://` HTML remains the tested default, but alternative origins may be considered when justified, with explicit user approval for distribution changes and preserved security, privacy and offline functionality; no legacy data migration is required. Never edit generated HTML directly.
- **Engineering:** typed, modular strict TypeScript, one six-kind exam runtime, no untyped parallel v11 implementation or casual `any`/`@ts-ignore`/`@ts-nocheck`.
- **Integrity:** immutable content-hashed paper/question/key/media snapshots, original/reviewed provenance; scoring and answer events validated and frozen; race-safe `saveRevision`, checked additive compact backup v4, explicit self-assessed writing marks and FSRS ratings; no pre-submit key disclosure.
- **Editorial:** user-approved reviewed CGL `caution` fallback retains published key B in disputed 6 Oct Q62 and scores it (+2/−0.5), while original source invalid is excluded. Dispute is disclosed clearly only after submission. The real paper/key JSON must remain unchanged.
- **Scoring:** component partial marks must not exceed declared full credit; validated blank awards, negative mark floor, matching uniqueness and multiple-select key/cardinality envelopes were repaired in Pass 17 and independently rechecked in Pass 23. Never relax these constraints merely to satisfy fixtures.
- **Storage and backup (binding clean-break D38):** This is a **new application**. No compatibility with earlier preference/data/IndexedDB schemas, backup formats, migration, adapter or dual-write requirements. P45-B currently uses **SHA-covered compact backup v4** with unique immutable snapshots; no earlier backup-version reader exists. Choose future architecture using measured memory/cold-start/write performance, correctness, security and offline reliability, **not** migration or compatibility costs. Protect current functional score accuracy, correct sessions, meaningful recovery and no accidental data destruction. The earlier ~1.62 GB sampled heap at 1,600 synthetic repeated records improved to **97.8 MB** under P45-B; performance on different paper populations and physical devices remains unverified.
