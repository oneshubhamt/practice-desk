## Image storage and clarity decision (P47-3)

- **Study Director reference:** [`oneshubhamt/study-director`](https://github.com/oneshubhamt/study-director) keeps image **bytes as OPFS blobs**, indexed metadata in IndexedDB and performs authoring-time resize/WebP conversion for oversized pictures. Its attachment storage explicitly rejects direct `file://` operation. Reuse the proven **native modal, focus restoration, accessibility and background inertness design patterns**, not that storage architecture.
- **Practice Desk source-of-truth:** validated SHA-256 `data:image/*;base64` source assets (10 MiB/image and 20 MiB/package decoded media safety caps) are frozen with the paper/key and deduplicated per shared immutable hash in the `practiceDesk.shared.v1` IndexedDB `snapshots` store; per-attempt rows hold lightweight snapshot references. They are **not OPFS files, not separate IndexedDB Blob records and not PDF media**. An imported JSON exam is capped at 25 MiB. A modal reuses the currently authenticated `data:` URI *transiently*, does not create another persisted binary, and releases its enlarged image on close. No fetch or CDN.
- **Measured 2026 CGL source media:** five built-in banks total **92 embedded figures / about 0.306 MiB decoded**, largest approximately **67.5 KiB**. Compression is already modest; do not degrade line-art/math text through unrequested JPEG/WebP loss or blur to shave marginal bytes. Preserve full original pixels for zoom and pan. Per-asset maximum is a hard security bound, **not a preferred image target**.
- **Future authored exam input:** design a *measured, visually verified*, optional pre-freeze image preparation/optimization process if CAT/PGDBA graphics actually need it. Consider WebP/PNG based on line detail, native size, decoded dimensions, target file-size limits and reversible source metadata; accept the smaller file **only if clarity is not impaired**, then recompute the content SHA before freezing/importing. This is separate from the viewer, not an excuse to mutate existing frozen image hashes or silently convert already-imported images.

**P47-3B quality/size policy:** Library → **Prepare image for a bank**. Default diagrams/math/text images remain byte-identical. For photographs only, quality-0.98 WebP must save ≥15% and pass conservative pixel screening; the user reviews original and candidate at 100–400% and checks approval before downloading a new `media` JSON entry. New simple authored banks accept `media`, `imageIds`, `optionImageIds`; SHA-256 is calculated and verified at import, and assets are shared per frozen source instead of copied per attempt. **No** compression of already-signed packages or stored attempt images, network use, PDF generation or OPFS migration. [D47 and data contract](docs/architecture/DATA_CONTRACTS.md).
